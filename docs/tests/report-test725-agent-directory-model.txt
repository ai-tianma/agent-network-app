#725 directory model, local prerequisite only
===========================================
Base: app main b9a3e1ec9e7f7a2677790632501f0edba5ed7151.
Source/contract review: requirement events 30442 and 30444.

This slice adds a pure read-model and its tests. It is NOT wired to the reader,
Agent list/search UI, or NodeDetailScreen and is NOT an end-to-end fix/release.

Inputs must already be authorized Hub reads. A caller-generated scopeKey must
bind the current account/auth epoch, requested scope and logical read generation.
The model is not an authorization oracle and complete=true is a reader claim,
not proof that HTTP collection really finished. The future reader must establish
both facts and ignore obsolete requests before supplying these snapshots.

Registered rows have a discriminated source, not an invented Session.status.
Only exact (network_id, node_id) identities can consume a genuine session.
Missing/ambiguous identity, unsuccessful or incomplete reads, or mismatched scope
cannot establish no-session. Existing session-only rows are preserved. Unknown
node records do not inherit a default network or an alias/hostname binding.
Returned directory node facts exclude capabilities, config and online timestamps.
No lifecycle request, persistence, network fetch, session write, or credential access.

Reader slice (same branch, still no UI wiring)
---------------------------------------------
src/agent-directory-reader.ts reads the two authorized endpoints and nothing else:
`GET /api/nodes` (no network filter) and `GET /api/status` (no `light=1`, because the
light projection omits node_id unless one node is filtered, so it cannot establish
identity). Bearer auth comes from the caller's HubConfig; this module never widens
visibility and never mints a scope key — an empty expected scope fails closed.

Only directory facts are copied (node_id, network_id, alias, node_name, runtime /
alias, status, ids, updated_at, runtime). Capability flags, config snapshots and
telemetry never enter the directory. Non-object rows are dropped. Non-2xx, ok:false,
non-JSON, abort/timeout and thrown fetches all become `unavailable`; they never
degrade into an empty list, so a failed read cannot become "no session".

Targeted verification (offline, injected fetch):
  docker run ... --entrypoint bun <image> --no-install src/agent-directory-reader.test.ts
  12/12 passed

Not covered / explicitly not claimed: no real Hub request was made in this slice, so
real ACL (no-grant/grant/revoke), pagination and Hub-version behaviour are unproven;
/sapi/status full projection is heavy (no light+node_id for all rows), so wiring it
into the 10 s AgentsScreen poll without caching would be a cost regression and is not
done here. UI wiring, the old-product red control and normal CI remain open.
